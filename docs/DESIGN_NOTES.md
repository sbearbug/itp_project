# Apple 设计原则参考与改造记录

## 参考范围

本次只阅读项目内临时保存的 `apple-design.md` 与 `mobile-native.md`。两份资料来自
`emilkowalski/skills`，仅用于提炼设计原则；不执行文档中的脚本或命令，不安装其推荐依赖。
项目仍以 Material 3、Android 交互习惯和现有六套语义主题为准。

## 适用于本 App 的原则

- **即时响应**：按下时立即给出状态反馈，避免只在点击释放后才响应；卡片用缩放回弹，
  其余可点元素用底色加深，两者都由 pointer-down 立即起效（列表卡片保留 60ms 防误触延迟，
  见文末 v1.10 一节）。
- **空间连续与可预测**：进入和退出沿同一路径；底部菜单从底部出现并回到底部，页面返回与
  进入保持对称。手势中的活动卡片继续 1:1 跟随触点，释放后从当前画面位置回到目标。
- **克制的物理感**：普通 UI 使用接近临界阻尼、无明显弹跳的节奏；只有用户直接推动的面板、
  卡片和展开控件使用轻微弹簧感。用 CSS `linear()` 描述缓动，不引入动画库。
- **排版层级**：系统中文字体优先；字号、字重、行高和字距协同建立层级。Oswald 只保留给
  台历日期数字，并继续使用等宽数字。
- **留白与映射**：按 4px 基础节奏统一页面、卡片、字段和操作区间距，让相邻关系代替多余
  分隔线；操作继续靠近其影响的内容。
- **移动端原生手感**：保留安全区、动态视口、16px 输入字号、按下反馈、正确的 `touch-action`
  与系统栏同步；桌面模拟只能验证结构，触感仍以 Android 真机为准。
- **简单而非空洞**：保留完成任务所需上下文，减少重复边框、重阴影和装饰，不隐藏现有功能。

## 不采用的内容

- 不采用 iOS 导航栏、左边缘滑动返回、iOS 分段控件、操作表、悬浮玻璃工具栏等组件；顶部
  应用栏、Android 返回键、FAB 和底部菜单全部保留。
- 不使用点击水波纹（v1.10 起改为缩放回弹与底色加深两套反馈，见文末）。
- 不改变 Android 手势含义，也不加入 iOS 式整页交互返回。
- 不采用文档建议的大面积毛玻璃。当前界面保持实体语义表面和遮罩，不增加
  `backdrop-filter`，避免 Android WebView 合成开销。
- 不引入 Motion、Framer Motion 或其他依赖。弹簧节奏只用 CSS `linear()`。
- 按用户补充要求，本轮不新增“减少动态效果”适配；已有兼容规则保留，不主动删除。
- 不采用资料中会改变功能、模块接口、数据格式、原生插件或构建配置的建议。

## 计划修改清单

1. 统一标题、正文、元信息、标签和表单说明的字号、字重、行高与字距层级。
2. 统一 4px 间距节奏和圆角层级：字段/小容器、卡片、底部面板/对话框分别成组。
3. 删除今天卡片、活动卡片、设置入口和已结束分组中不必要的边框或装饰性阴影，以留白、
   表面和内容层级区分信息；表单边界与选中态等必要可供性仍保留。
4. 为页面切换、底部面板、卡片侧滑回位、展开和确认反馈统一时长，并使用 CSS `linear()`
   弹簧缓动；撕页仍是唯一装饰性动效。
5. 补齐移动端基础细节：控件禁止长按选中文字、点击使用 `touch-action: manipulation`、根滚动
   避免浏览器下拉刷新，输入控件在触屏上不低于 16px。
6. 在六套主题下做静态构建与界面切换检查，并明确仍需 Android 真机确认的触感项目。

## 实际修改与取舍

### 已完成

- 重新整理标题、正文、元信息、标签、表单说明和按钮文字的字号、字重、行高与字距；中文
  继续使用系统字体，台历数字继续使用 Oswald，没有新增字体。
- 建立小容器 12px、卡片 18px、面板/对话框 28px 的圆角层级，并用 4px 的倍数整理页面
  边距、分组间距、卡片内边距和设置项间距。
- 移除“今天”卡片、活动卡片、设置入口、识别结果表面和已结束分组上不承担状态表达的
  边框及阴影；输入字段、选中态、紧急态等需要明确可供性的边界继续保留。
- 新增三条 CSS `linear()` 动效曲线：直接过渡、轻微弹簧和按压反馈。页面切换、底部面板、
  卡片回位、展开、确认层和批量工具栏使用统一节奏；没有引入动画库，撕页仍是唯一装饰性
  动效（当时保留的 Material 水波纹已在 v1.10 移除，见文末）。
- 补充 `interactive-widget=resizes-content`、`100dvh`、根滚动边界、内层滚动隔离、16px 输入
  字号、`touch-action: manipulation` 和控件长按保护。活动卡片原有 `pan-y` 横滑协调规则优先级
  保持不变。
- 在浏览器中逐一切换烟雨、坚冰、苔绿、暖阳、石墨、坚冰（深色），确认语义变量、即时
  切换和 CSS `linear()` 均生效；生产构建通过。

### 最终没有做

- 没有实现面板逐像素跟手、释放速度投射、橡皮筋边界或动画中途重新抓取。这些需要修改
  JavaScript 手势状态与功能逻辑，超出本任务允许范围，也会提高 Android 返回键和滚动冲突风险。
- 没有加入 haptic、声音或新的系统插件，因为它们不是视觉细节，且会触及原生接口和构建配置。
- 没有采用任何毛玻璃；实体语义表面已能表达层级，增加模糊只会提高 Android WebView 合成
  成本。
- 没有替换 Material 组件，也没有加入 iOS 导航、边缘返回、操作表或 iOS 分段控件。
- 按用户补充要求，没有为本轮新动效另增减少动态效果逻辑；项目原有规则仍保留。
- 未宣称完成真机触感验证。仍需在 Android 手机上检查按压响应、底部面板起落、活动卡片
  横滑回位、软件键盘弹出后的可视高度，以及旧款设备上的滚动帧率。

## 后续交互优化实施记录

在视觉体系确认后，进一步完成了先前暂缓的四类直接操控优化，仍未引入第三方动画库：

- 设置底部弹层改为 Pointer Events 驱动的逐像素跟手手势。位移、遮罩透明度、边界阻尼、
  松手速度和当前位置共同构成开合状态；落位过程中可以重新按住并从当前帧继续拖动。
- 活动卡片左滑增加方向阈值、纵横方向锁、两端阻尼、最近速度投射和渐进式操作显现；
  快划与慢拖使用不同判定，落位动画同样允许中途重新抓取。
- 所有可点击控件统一 pointer-down、移出取消、移回恢复、pointer-up/cancel 清理的按压生命周期；
  异步操作同时使用禁用态和 `aria-busy`，减少重复触发和反馈不一致。
- 列表页与添加/编辑页转场改由 Web Animations API 驱动。返回操作会读取当前计算样式，
  因此能够中断尚未完成的进入动画并从当前可见位置反向运行。

本轮没有增加触觉插件、音效或业务状态，也没有调整模块接口与 Event 数据格式。浏览器已验证
卡片左滑、设置弹层跟手开合、进入过程中立即返回及控制台错误；Android WebView 上的速度阈值、
系统返回键中断和 60Hz/120Hz 设备手感仍需真机复核。

## 点击反馈统一（v1.10）

按用户要求把按下反馈从「Material 水波纹 + 极轻缩放」整体换成两套互斥反馈，并移除水波纹。
本节结论**取代上文所有“保留水波纹”的描述**。

### 做了什么

- **删除水波纹**：移除 `material-ripple` 关键帧、`::after` 圆点状态层、`--ripple-x/--ripple-y`
  内联变量和 `ripple-active` 状态类；`::after` 被复用作状态色层。全局
  `-webkit-tap-highlight-color: transparent`，去掉 WebView 默认点击高亮。
- **卡片缩放回弹**：活动卡片、今日台历卡片、设置页主题色块按下 `scale: .965`（90ms
  ease-out），松开由新增令牌 `--motion-press-release` 的弹簧曲线在 420ms 内回到 1。
- **按钮底色加深**：所有按钮（含 FAB）、菜单项、设置列表项、应用栏图标按钮用 `::after`
  铺状态色，按下 60ms 淡入、松开 220ms 淡出，不缩放也不位移。状态色按元素类型从主题
  派生：实心按钮 `--on-btn` 14%、悬浮按钮 `--on-accent` 14%、表面元素 `--text` 8%。
- **统一驱动**：`setupPressFeedback` 用 Pointer Events（down/move/up/cancel/leave）与键盘
  （空格、回车）驱动同一个 `.is-pressed` 状态类，键盘在 `focusout` 与窗口失焦时清理。

### 取舍与踩到的坑

- **卡片用 `scale` 而不是 `transform`**。活动卡片的 `transform` 已被左滑手势占用，
  v1.9 记录里那个「CSS 过渡与 JS 动画落点值恰好重合所以没暴露」的隐患正源于两套系统
  争抢同一属性。改用独立的 `scale` 后两个属性可以叠加，冲突从根上消失。
- **状态色按按钮类型显式分档**，而不是统一取 `currentColor`。两者在当前八套主题下结果
  一致，但显式列出可以在换主题或改按钮配色时直接看出哪一类失配。
- **特异度坑**：`button:not(:disabled)::after`（0,1,2）的权重高于 `.fab::after`（0,1,1），
  导致实心按钮和 FAB 都拿到表面元素的 8% 状态色。改用
  `button:where(:not(:disabled))::after` 把 `:not()` 的权重归零后覆盖规则才生效。
- **列表卡片 60ms 延迟**：延迟窗口内移动超过 8px 或收到 `pointercancel` 就整轮放弃，
  避免滑动列表时卡片闪动。（该延迟一度导致极短点按看不到反馈，v1.11 已修正，见下节。）
- 减少动态效果时卡片不缩放，按钮的状态色变化保留。

### 仍未验证

- Android WebView 对 `scale` 独立属性的兼容性（minSdk 24 / target 36），以及 90ms 按下、
  420ms 回弹在 60Hz/120Hz 真机上的实际观感与跟手程度。

## 固定下压深度与放慢页面转场（v1.11）

真机试用后发现两个问题：点按过快时卡片下压深度不足、动画看着不明显；页面进出转场偏短、
显得仓促。本轮只调这两处。

### 固定下压深度

- 原因：60ms 防误触延迟之后才开始 90ms 的下压过渡。点按总时长不足 150ms 时，抬起手指
  会中断过渡，卡片只压到 0.965 与 1 之间的某个位置就回弹，深度随点按时长变化。
- 做法：`pointerup` 时若下压尚未满 90ms，先补足剩余时间再移除 `.is-pressed`，让 420ms
  弹簧总是从完整深度开始。若抬起时还没进入按下态（点按短于 60ms），则当场补一次下压。
  90ms 这个常量在 JS 里是 `PRESS_DEPTH_DURATION`，**必须与 CSS 中 `.is-pressed` 的 scale
  过渡时长保持一致**，改一处要改两处。
- 取消路径（`pointercancel`、`pointerleave`、`focusout`、窗口失焦）不做补齐，立即释放；
  滚动放弃仍然优先，滑动列表时卡片依旧不会闪。
- 实测：点按 15 / 40 / 70 / 120 / 250 / 500ms 六种时长，下压最低点都是 0.9650，极差 0.0000。

### 放慢页面转场

| 转场 | 原时长 | 现时长 |
|---|---|---|
| 列表 → 添加/编辑（滑入） | 260ms | 380ms |
| 返回：当前页滑出 | 240ms | 340ms |
| 返回：下一页淡入 | 190ms | 300ms |
| `.page--fade-in`（首帧） | 220ms | 320ms |
| `.page--enter-right` / `.page--exit-right` | 250ms | 380ms |

实测挂钟耗时：进入子页面约 396ms（原约 260ms），返回列表约 677ms（原约 430ms）。
`prefers-reduced-motion` 下仍保持 180ms 的淡入淡出，不跟随延长。

### 顺带修掉：右下角加号在长列表里“消失”

同一个包里还修了一个 v1.8 遗留的结构性 bug。`.page` 上的 `will-change: transform`
会为 `position: fixed` 的后代创建包含块，而 `.fab` 是渲染在 `<main class="page">`
里面的，于是它相对整页（而不是视口）定位：列表 18 项时，加号在 `scrollY=0` 的矩形
top 是 2843px，而视口只有 915px。列表越长它沉得越深，再叠加“向下滚动即隐藏”的逻辑，
加号在实际能看见它的位置恰好被隐藏，所以表现为凭空消失。短列表因为 `.page` 只有
`min-height: 100vh`，加号碰巧落在视口底部，看不出问题。

修法是把 `.fab`、`.bulk-toolbar`、`#toast-root` 三个 fixed 浮层移出 `.page`，改为
`#app` 的直接子元素（`#app` 只有 `position: relative`，不创建包含块）。设置抽屉打开时
`#app` 自身会位移，浮层跟着一起走，这是预期效果。约束已写进 `ARCHITECTURE.md`，
避免以后有人为了“结构清晰”把浮层挪回页面容器里。

## 信息层级与状态表达整理（v1.12）

这一轮把列表页和添加页的信息层级重新理了一遍，并修掉状态栏、返回按钮和“加入日历”
按钮的三个问题。没有改动 Event 数据格式，也没有新增依赖。

### 状态栏

- **根因是图标极性传反了**。Capacitor 的 `Style` 枚举命名与直觉相反：
  `Style.Dark` 是“深色背景配浅色图标”，`Style.Light` 是“浅色背景配深色图标”。
  原代码写的是 `dark ? Style.Light : Style.Dark`，于是深色主题下把深色图标画在了
  深色状态栏上。改成 `dark ? Style.Dark : Style.Light`。
- 背景色原先取 `:root` 的 `--bg`，但页面实际底色是 `body` 的 `--surface`，两者在
  浅色主题下分别是 `#F4F4F6` 和 `#FFFFFF`，肉眼能看到色差。现在直接读 `body` 的
  计算背景色并转成十六进制，`meta[theme-color]` 与原生状态栏用同一个值。
- Android 15+ 上 `StatusBar.setStyle` 可能不生效，所以在 `SystemBarsPlugin` 里用
  `setAppearanceLightStatusBars()` 兜一次底，和导航栏共用同一极性。
- 主题或深浅模式切换时 `applyTheme()` 会重新走一遍，所以是即时生效的。

### 布局决策

- 活动数量从独立徽章改成标题后的同排小号文字，顶部应用栏因此只剩“⋮”一个按钮，
  视觉上安静很多；“管理”进菜单后仍然是完整功能，只是不再常驻占位。
- 卡片右侧原本分两行显示“时间”和“地点”，现在合并成一行“时间 · 地点”。信息密度提高，
  卡片高度一致；跨天活动同一行显示日期区间，比单看开始时间更能表达“这是个持续活动”。
- 跨年区间两端都带年份。只给开始端加年份会渲染成“2025年12月30日–1月2日”，
  读起来像同年，反而更糊涂。
- 类型标签去掉底色只留次要文字，和状态胶囊区分开：底色专用于表达状态。
  已报名用 `--accent` 实心是三种状态里唯一的强表达，符合“用户已经完成动作”的语义。

### 需要确认的一处判断

只有日期、没有具体时间的单日活动，右侧第二行显示“全天”。需求里写的是“无时间显示
时间待定”，但这类活动是**已知全天**而不是**时间未知**，用“时间待定”会误导。
如果更希望严格按字面来，改 `cardScheduleText()` 里 `event.allDay` 那个分支即可。

### 添加页

- 选图入口的“＋”加描边方框换成内联 SVG 线框图片图标：方框本身就是在画一个矩形，
  再加个加号等于两套符号叠加。
- “从文字提取”在输入为空时 `disabled` 并置灰，有内容才变成实心主按钮。副作用是
  原来“空输入点一下弹提示”的路径不再可达，那段提示逻辑留作兜底。
- 文本域改成 `resize: none` + 随内容增高，超过 8 行转内部滚动；上限按计算后的行高
  推导（当前 25.6 × 8 + 内边距 + 边框 ≈ 232.8px），换字号时不需要改这个数字。

## 弹层视图衔接与模式滑块（v1.12 补充）

同一版本内追加的两处动效，都是“让状态变化看起来是连续的”这条原则的延伸。

### 设置弹层的视图切换

- 原来点“外观”或“识别接口”是整块 `innerHTML` 重绘，菜单瞬间被替换，没有任何过渡，
  感觉像跳了一下。现在进入子视图从右侧滑入 380ms，返回时先把当前视图向右推出 340ms、
  再把菜单淡入 300ms——时长与缓动直接沿用页面路由那一套，所以弹层内外的“进退方向”
  是同一个语言。
- 实现上有个顺序要求：返回必须先对现有的 `.settings-view` 播完滑出动画再重建 DOM。
  如果先重绘，旧内容已经没了，就没有东西可以滑出去，只剩下新内容的淡入，
  方向感会丢掉一半。
- 模式和主题的选择改成就地更新（只改 `aria-pressed`、勾号和滑块位置），不重绘。
  重绘会把滑块元素一起换掉，位置变化就变成瞬移了。

### 模式滑块

- 选中的底色从“按钮自己的背景”改成独立的一个绝对定位滑块，靠 `transform` 平移。
  这样切换深浅模式时是一块东西滑过去，而不是两个按钮的底色此消彼长。
- 踩了两个坑，都记在代码注释里了：
  1. **改自定义属性不会触发过渡**。最初用 `--mode-index` 驱动 `transform: translateX(calc(var(--mode-index) * ...))`，
     逐帧采样发现只有两个取值——滑块是瞬移的。浏览器不把 `var()` 代入结果的变化当作
     可过渡变化，必须把 `transform` 直接写在行内样式上。
  2. **主题切换时滑块会被顺带清掉**。`.theme-transition *` 用 `!important` 把 `transition`
     简写整体换成了只剩颜色属性，位移过渡也被清掉，于是每次切换深浅模式滑块都瞬移。
     在该规则旁单独为滑块还原了位移过渡。
- 减少动态效果时滑块不做过渡，直接落位。

### 顺带修掉的一帧问题

v1.11 的卡片下压补齐用 90ms，正好等于 CSS 过渡时长，于是“取消按下态”的时刻与
“过渡结束”的时刻完全重合，触底那一帧可能落在两次渲染之间——逐帧采样偶尔只能测到
0.9685 而不是 0.965。多留约一帧（16ms）后，触底那帧一定被渲染出来，深度在不同帧率下
都稳定。这也解释了为什么之前 v1.11 的深度测试偶尔会失败。
