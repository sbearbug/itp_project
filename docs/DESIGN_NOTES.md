# Apple 设计原则参考与改造记录

## 参考范围

本次只阅读项目内临时保存的 `apple-design.md` 与 `mobile-native.md`。两份资料来自
`emilkowalski/skills`，仅用于提炼设计原则；不执行文档中的脚本或命令，不安装其推荐依赖。
项目仍以 Material 3、Android 交互习惯和现有六套语义主题为准。

## 适用于本 App 的原则

- **即时响应**：按下时立即给出状态反馈，避免只在点击释放后才响应；保留 Material 水波纹，
  并让非手势控件的按压状态更连贯。
- **空间连续与可预测**：进入和退出沿同一路径；底部菜单从底部出现并回到底部，页面返回与
  进入保持对称。手势中的活动卡片继续 1:1 跟随触点，释放后从当前画面位置回到目标。
- **克制的物理感**：普通 UI 使用接近临界阻尼、无明显弹跳的节奏；只有用户直接推动的面板、
  卡片和展开控件使用轻微弹簧感。用 CSS `linear()` 描述缓动，不引入动画库。
- **排版层级**：系统中文字体优先；字号、字重、行高和字距协同建立层级。Oswald 只保留给
  台历日期数字，并继续使用等宽数字。
- **留白与映射**：按 4px 基础节奏统一页面、卡片、字段和操作区间距，让相邻关系代替多余
  分隔线；操作继续靠近其影响的内容。
- **移动端原生手感**：保留安全区、动态视口、16px 输入字号、按下反馈、正确的 `touch-action`
  与系统栏同步；桌面模拟只能验证结构，触感仍以 Android 真机为准。
- **简单而非空洞**：保留完成任务所需上下文，减少重复边框、重阴影和装饰，不隐藏现有功能。

## 不采用的内容

- 不采用 iOS 导航栏、左边缘滑动返回、iOS 分段控件、操作表、悬浮玻璃工具栏等组件；顶部
  应用栏、Android 返回键、FAB、底部菜单和 Material 水波纹全部保留。
- 不改变 Android 手势含义，也不加入 iOS 式整页交互返回。
- 不采用文档建议的大面积毛玻璃。当前界面保持实体语义表面和遮罩，不增加
  `backdrop-filter`，避免 Android WebView 合成开销。
- 不引入 Motion、Framer Motion 或其他依赖。弹簧节奏只用 CSS `linear()`。
- 按用户补充要求，本轮不新增“减少动态效果”适配；已有兼容规则保留，不主动删除。
- 不采用资料中会改变功能、模块接口、数据格式、原生插件或构建配置的建议。

## 计划修改清单

1. 统一标题、正文、元信息、标签和表单说明的字号、字重、行高与字距层级。
2. 统一 4px 间距节奏和圆角层级：字段/小容器、卡片、底部面板/对话框分别成组。
3. 删除今天卡片、活动卡片、设置入口和已结束分组中不必要的边框或装饰性阴影，以留白、
   表面和内容层级区分信息；表单边界与选中态等必要可供性仍保留。
4. 为页面切换、底部面板、卡片侧滑回位、展开和确认反馈统一时长，并使用 CSS `linear()`
   弹簧缓动；撕页仍是唯一装饰性动效。
5. 补齐移动端基础细节：控件禁止长按选中文字、点击使用 `touch-action: manipulation`、根滚动
   避免浏览器下拉刷新，输入控件在触屏上不低于 16px。
6. 在六套主题下做静态构建与界面切换检查，并明确仍需 Android 真机确认的触感项目。

## 实际修改与取舍

### 已完成

- 重新整理标题、正文、元信息、标签、表单说明和按钮文字的字号、字重、行高与字距；中文
  继续使用系统字体，台历数字继续使用 Oswald，没有新增字体。
- 建立小容器 12px、卡片 18px、面板/对话框 28px 的圆角层级，并用 4px 的倍数整理页面
  边距、分组间距、卡片内边距和设置项间距。
- 移除“今天”卡片、活动卡片、设置入口、识别结果表面和已结束分组上不承担状态表达的
  边框及阴影；输入字段、选中态、紧急态等需要明确可供性的边界继续保留。
- 新增三条 CSS `linear()` 动效曲线：直接过渡、轻微弹簧和按压反馈。页面切换、底部面板、
  卡片回位、展开、确认层和批量工具栏使用统一节奏；没有引入动画库，撕页仍是唯一装饰性
  动效，Material 水波纹继续保留。
- 补充 `interactive-widget=resizes-content`、`100dvh`、根滚动边界、内层滚动隔离、16px 输入
  字号、`touch-action: manipulation` 和控件长按保护。活动卡片原有 `pan-y` 横滑协调规则优先级
  保持不变。
- 在浏览器中逐一切换烟雨、坚冰、苔绿、暖阳、石墨、坚冰（深色），确认语义变量、即时
  切换和 CSS `linear()` 均生效；生产构建通过。

### 最终没有做

- 没有实现面板逐像素跟手、释放速度投射、橡皮筋边界或动画中途重新抓取。这些需要修改
  JavaScript 手势状态与功能逻辑，超出本任务允许范围，也会提高 Android 返回键和滚动冲突风险。
- 没有加入 haptic、声音或新的系统插件，因为它们不是视觉细节，且会触及原生接口和构建配置。
- 没有采用任何毛玻璃；实体语义表面已能表达层级，增加模糊只会提高 Android WebView 合成
  成本。
- 没有替换 Material 组件，也没有加入 iOS 导航、边缘返回、操作表或 iOS 分段控件。
- 按用户补充要求，没有为本轮新动效另增减少动态效果逻辑；项目原有规则仍保留。
- 未宣称完成真机触感验证。仍需在 Android 手机上检查按压响应、底部面板起落、活动卡片
  横滑回位、软件键盘弹出后的可视高度，以及旧款设备上的滚动帧率。

## 后续交互优化实施记录

在视觉体系确认后，进一步完成了先前暂缓的四类直接操控优化，仍未引入第三方动画库：

- 设置底部弹层改为 Pointer Events 驱动的逐像素跟手手势。位移、遮罩透明度、边界阻尼、
  松手速度和当前位置共同构成开合状态；落位过程中可以重新按住并从当前帧继续拖动。
- 活动卡片左滑增加方向阈值、纵横方向锁、两端阻尼、最近速度投射和渐进式操作显现；
  快划与慢拖使用不同判定，落位动画同样允许中途重新抓取。
- 所有可点击控件统一 pointer-down、移出取消、移回恢复、pointer-up/cancel 清理的按压生命周期；
  异步操作同时使用禁用态和 `aria-busy`，减少重复触发和反馈不一致。
- 列表页与添加/编辑页转场改由 Web Animations API 驱动。返回操作会读取当前计算样式，
  因此能够中断尚未完成的进入动画并从当前可见位置反向运行。

本轮没有增加触觉插件、音效或业务状态，也没有调整模块接口与 Event 数据格式。浏览器已验证
卡片左滑、设置弹层跟手开合、进入过程中立即返回及控制台错误；Android WebView 上的速度阈值、
系统返回键中断和 60Hz/120Hz 设备手感仍需真机复核。
