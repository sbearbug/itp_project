# 智谱提取实测（2026-10-02）

使用项目 production 配置的 glm-4.6v-flash，thinking=disabled、temperature=0.1，
通过脚本捕获 src/extract.js 实际构建的请求体，再向同一个接口发送请求。
只发送自编通知，没有使用私人通知或图片，没有记录密钥。手机上的自定义接口配置
不在此桌面测试范围内。测试为真实文本 API 调用，不能替代海报图片或 Android 桥接测试。

## 样例与基线

| 样例 | 原提示词实际结果 |
| --- | --- |
| 单活动：明确日期、时间、地点、报名网址 | HTTP 200，数组可解析，但带代码围栏，漏 actions |
| 三个招新：部分时间待通知 | HTTP 200，数组可解析，allDay 类型/全天结束时间不一致 |
| 读书会：引号、反斜杠、方括号、网址 | HTTP 200，数组可解析 |
| 摄影社招新：时间地点待通知 | HTTP 200，description 内出现未转义的实际换行，JSON.parse 失败 |
| 食堂闲聊与界面文字 | HTTP 200，返回空数组，符合预期 |
| 多日志愿活动与问卷网址 | HTTP 200，数组可解析，但全天 end 未覆盖最后一天 |

六组基线均返回代码围栏（App 原本已能去掉）；一组无法解析。
这是一次小样本结果，不代表模型的长期失败率。

## 提示词调整及复测

- 明确外层数组（包括只有一个活动时）、完整 11 字段和各字段类型。
- 明确字符串中的换行、双引号、反斜杠转义，避免模板换行被直接复制。
- 用完整数组结构示意取代含“日期或 null”的伪 JSON 类型示例。
- 真实通知与规则/示例分开，重复强调非事项返回 []，不照抄示例活动。
- 补充全天单日/多日的排他结束日期、待通知字段、缺失值及输出自检要求。
- 对标题采用不含嵌套 ASCII 引号的简短概括，降低引号序列化风险。

共进行五轮完整的六组测试（含基线），另有四个最终针对性样例，共 34 个有效
样例请求：28 个 HTTP 200、6 个 HTTP 429。限流响应均为 code=1305，原文
“该模型当前访问量过大，请您稍后再试”。不是测试脚本推断出的错误原因。
早期脚本捕获请求体的异步等待错误导致一次空请求 HTTP 400，修复后重新测试；
该请求及中断批次不计入上述有效样例统计。

复测揭示：增加格式约束并不能稳定保证模型遵守协议；尝试单对象语法示例时，
模型会跟随示例而忘记外层数组，已移除该示例。带实际活动的示例还会污染空通知
结果，因此改为仅结构示意。多轮出现非法引号或单对象返回，不能宣称全部修复。
最终四个针对性样例中：空通知与多日区间均返回可解析、字段完整的数组；
待通知样例仍返回有错误尾引号的单对象；特殊字符样例被 1305 限流，没有得到结果。
上一轮完整六组中四组数组可解析、一组引号解析失败、一组限流。

本次仅调整提示词，不修改解析器、错误重试策略、Event 格式、模型或模块接口。
要获得稳定成功率，后续仍需要验证模型支持的结构化输出能力，或增加有边界的
格式校验/纠正与限流退避；不能把这些问题宣称成提示词已经解决。
